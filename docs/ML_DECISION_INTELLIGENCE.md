# HDIP — Machine Learning & Decision Intelligence Guide

## Overview

HDIP implements a four-model ML pipeline, a SHAP-based Explainability layer, a complete MLOps framework, and a quantitative Decision Intelligence engine built on top of those predictions.

---

## ML Models

### 1. Demand Forecast Model
- **Algorithm**: Facebook Prophet (time-series) + ensemble boosting adjustment
- **Input features**: Day-of-week, month, holidays, recent admission trend, historical baseline volume
- **Output**: 3–14 day forward-looking patient volume forecast with daily confidence intervals
- **Prediction Confidence**: 0.80–0.95 based on training RMSE and prediction horizon
- **Use case**: Staffing pre-authorization, bed reservation planning, supply ordering

### 2. Bed Occupancy Prediction Model
- **Algorithm**: XGBoost regressor with occupancy trend features
- **Input features**: Department, base_occ_pct, horizon_hours, seasonal multiplier, historical peak patterns
- **Output**: Predicted peak occupancy % with 24–72h horizon, current capacity buffer
- **Prediction Confidence**: 0.85–0.94
- **Use case**: Overflow bed authorization, transfer coordination, discharge planning

### 3. ED Wait Time Prediction Model
- **Algorithm**: Gradient Boosting Regressor
- **Input features**: ED census, waiting_count, acuity_level (ESI 1–5), hour_of_day
- **Output**: Predicted wait time in minutes, LWBS (Left Without Being Seen) risk %, risk_level
- **Prediction Confidence**: 0.78–0.90
- **Use case**: Real-time rapid triage protocol activation, boarding decisions, nurse reallocation

### 4. Readmission Risk Model
- **Algorithm**: XGBoost Classifier + Logistic Regression ensemble (probability calibration)
- **Input features**: age, gender, diagnosis, comorbidity_count, length_of_stay_days, esi_acuity, prior_admissions_12m, prior_ed_visits_6m, payer
- **Output**: 30-day readmission probability (0–1), risk_tier (very_high/high/moderate/low)
- **Prediction Confidence**: 0.82–0.93 (calibrated probability)
- **Use case**: Discharge intervention targeting, care transition planning, social work referrals

## Explainable AI (XAI) — SHAP

Every prediction is accompanied by a SHAP-based explanation:

```python
explanation = {
  "top_factors": [
    {"feature": "prior_admissions_12m", "shap_value": 0.42, "direction": "positive", "plain_english": "Patient had 3 prior admissions in last 12 months, significantly increasing readmission risk."},
    {"feature": "comorbidity_count",    "shap_value": 0.31, "direction": "positive", "plain_english": "4 active comorbidities compound the readmission likelihood."},
    {"feature": "age",                  "shap_value": 0.18, "direction": "positive", "plain_english": "Age 70+ patients statistically have higher 30-day readmission rates."}
  ],
  "explanation_type": "SHAP",
  "model_type": "readmission_risk",
  "total_shap_contribution": 0.91
}
```

**Key design decisions:**
- SHAP values are **signed** (positive = increases risk/wait/volume, negative = decreases)
- Plain-English translations are generated by mapping feature name + direction + magnitude
- Displayed in the frontend as ranked attribution cards with visual bar indicators

## Multi-Level Decision Confidence Framework

Each recommendation carries a 4-dimensional confidence profile:

| Layer | Formula | Description |
|---|---|---|
| **Prediction Confidence** | From ML model calibration | Raw model prediction certainty |
| **Recommendation Confidence** | `base_pred_conf × category_weight` | Adjusted for recommendation certainty by domain |
| **Scenario Simulation Confidence** | `base × complexity_penalty × extrapolation_penalty` | Penalized for parameter complexity and OOD inputs |
| **Overall Decision Confidence** | Weighted Harmonic Mean(P, R, S) | Penalizes the weakest layer most aggressively |

**Weighted Harmonic Mean (WHM)** was chosen over arithmetic mean specifically because it **penalizes weak layers disproportionately** — a recommendation with 95% prediction confidence but 40% scenario confidence should NOT yield 67% overall (arithmetic); the WHM yields a lower, safer 57%, correctly reflecting the uncertainty.

## Recommendation Engine

### Priority Scoring Formula
```
priority_score = (0.35 × risk_level_score)
              + (0.25 × urgency_score)
              + (0.25 × expected_improvement_score)
              - (0.15 × implementation_difficulty_score)
```

### Priority Tiers
| Tier | Score Range | Label | Expected Response |
|---|---|---|---|
| P1 | 75–100 | Critical — Immediate Action | Within 1 hour |
| P2 | 55–74 | High — Urgent Action | Within 4 hours |
| P3 | 35–54 | Medium — Planned Action | Within 24 hours |
| P4 | 0–34 | Low — Scheduled Review | Within 72 hours |

### Reasoning Chain
Every recommendation carries a 5-step transparency chain:
1. **ML Prediction** — what the model predicted and its confidence
2. **SHAP Attribution** — top features driving this outcome
3. **Impact Assessment** — risk level and financial exposure
4. **Recommendation Formula** — derived action quantity and rationale
5. **Expected Operational Outcome** — quantified projected improvement

## Scenario Simulator

### 8 Supported Scenarios

| Type | Parameters | Key Perturbations Applied |
|---|---|---|
| `increased_patient_arrivals` | surge_count, surge_duration_h | ed_census ↑, waiting_count ↑, demand_volume ↑ |
| `staff_shortage` | shortage_count, shift | waiting_count ↑, nurses_delta negative |
| `additional_staffing` | nurses_added, department | waiting_count ↓, nurses_delta positive |
| `bed_expansion` | beds_added, department | base_occ_pct ↓ (capacity-proportional) |
| `department_closure` | closed_dept, closure_pct | ed_census ↑, occ_pct ↑ (volume rerouted) |
| `equipment_downtime` | downtime_hours, treatment_time_increase | boarding ↑, waiting_count ↑ |
| `seasonal_demand_surge` | seasonal_factor, season_name | all volumes × multiplier |
| `mass_casualty_event` | mci_patient_count, high_acuity_pct | census → max, acuity → ESI 1/2 |

### Simulation Confidence Penalties
- **Complexity penalty**: −2% per scenario parameter provided above baseline
- **Extrapolation penalty**: −10% when any parameter exceeds 30% of training baseline range
- **WHM applied** across all layers before outputting overall simulation confidence

## Cascading Impact Analysis (7 Domains)

For each scenario, the CascadeImpactAnalyzer estimates second and third-order operational effects:

1. **Bed Occupancy Impact** — direct occupancy delta %, buffer capacity remaining
2. **ED Wait Time Impact** — direct wait time change in minutes, boarding cascade
3. **Staffing Demand Impact** — FTE gap, nurse-to-patient ratio impact
4. **Resource Utilization Impact** — supply consumption, equipment availability
5. **Operational Cost Impact (INR)** — staff overtime, disposable supply, setup costs
6. **Readmission Risk Impact** — quality degradation from staffing ratio strain
7. **Department Workload Impact** — load redistribution across affected departments

## MLOps Framework

### Model Registry
- Each trained model is versioned and registered with: name, version, algorithm, hyperparameters, training metrics (RMSE, MAE, F1, AUC-ROC), training dataset ID, training duration
- Active/archived flags control which version serves production predictions

### Model Monitoring & Drift Detection
- **Performance Monitoring**: Rolling prediction confidence tracking with latency histogram
- **Data Drift Detection**: Input feature distribution shift monitoring using reference baseline
- **Drift Severity Levels**: `none`, `low`, `medium`, `high`, `critical`
- **Alert Generation**: Automatic `OperationalAlert` creation when drift exceeds thresholds
- **Celery Background Jobs**: Drift detection runs as scheduled background tasks on Redis

### Monitoring Metrics Per Model
- Prediction confidence mean/std
- Inference latency (p50, p95, p99)
- Drift score (0–1 scale)
- Alert count (last 30 days)

## Decision Outcome Feedback Loop

After implementing a recommendation, administrators record actual outcomes across 6 dimensions:

| Dimension | Expected Source | Actual Source |
|---|---|---|
| Operational Improvement (%) | Recommendation formula | Admin-reported post-implementation |
| Financial Cost (₹) | Cost impact model | Actual expenditure |
| Wait Time Reduction (min) | ED wait model delta | Measured ED throughput data |
| Occupancy Change (%) | Bed occupancy model | Reported census data |
| Staffing Change (FTE) | Staffing formula | Actual staffing deployed |
| Resource Utilization Δ (%) | Resource model | Supply tracking system |

### Effectiveness Scores Computed
- **Prediction Accuracy Score** — how close the ML prediction was to actual
- **Recommendation Effectiveness Score** — how close the intervention outcome was to expected
- **Cost Estimation Accuracy Score** — cost model accuracy vs actual financial data

These roll up into the **Recommendation Quality Framework** dashboard for continuous model improvement.
